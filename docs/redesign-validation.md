# 0.2.0 重构验收

日期：2026-10-07。开发分支 codex/suzuri-usability-redesign；main 保持不变。

## 实施范围

写作界面采用单一滚动画布与底部上下文工具栏，参考 screenshot-reference 的工具分组方式，未复制桌面截图工具界面。语义配色参考 Neiro，红色用于主要交互，文稿使用中性表面。列表、设置、账号授权、图片插入均已重新组织。

草稿存储不再静默切到内存；初始化、读取、写入失败显式呈现。失败快照保留可重试；写入校验 origin/account 归属，首次注册迁移其他匿名本地草稿。保存重试不再触发发布。组合输入和跨块合并同步已修复；不能无损表示的多图内容禁止编辑。撤销/导入账号检查请求身份，避免迟到响应影响新账号。

## 本地检查与远程验证

Windows 无 Xcode。已做 Swift 语法解析、YAML 结构检查与 git diff --check；这些检查不能替代 Xcode 类型检查、XCTest 或实机截图。

GitHub 构建和测试独立运行。Release 的提交 SHA 应与目标测试运行一致；不要用“下载包已经生成”替代测试结论。

## 设备验收顺序

1. 新建三份草稿；中文输入、回车拆分、跨块合并、继续键入；退出重开检查内容。
2. 窄屏、横向空间变化、系统大字号和暗色模式检查工具栏、标题和长文滚动。
3. 打开 Postimages，选图上传，处理网站验证码，复制 Direct link 插入；取消、重试与空图片块替换。
4. 在 @telegraph 选择既有账号，取新登录链接，在应用连接；确认文章列表及旧文章编辑权限。测试过期链接、取消和错误 token。
5. 匿名状态发布其中一份草稿，其他两份仍可见。模拟网络失败，确认本地保存及重试。
6. 已发布页拉回、修改、更新，检查浏览器内容；含不支持格式的文章不可覆盖。
7. 撤销/切换账号和镜像时，旧请求不会清除新凭据，旧账号草稿不会被空内容覆盖。
8. 数据库故障时明确提示失败；重试只写本地。需要时通过“文章操作 → 导出文本”保留当前可读内容。

## 已知边界

- Postimages 采用真实网站上传，不提供未经验证的私有 API 自动上传；直链由用户明确插入。
- Telegram 登录参考项目的授权链路，但具体 Cookie 候选由官方 API 验证，不能把任意 cookie 当作账号 token。
- 暂无跨区块整篇撤销、iCloud 同步或后台发布队列。网络成功但本地记录失败会保留待保存状态，退出前再次保存关联路径。
- 预览包未签名；用户确认前不合并主分支。
